# Licencia

> Qué licencia tiene este repositorio, por qué, y qué distinción conviene no
> saltarse. El texto de la licencia está en [LICENSE](../LICENSE).

## QUÉ LICENCIA

**PolyForm Noncommercial License 1.0.0**, con el aviso requerido:

```
Required Notice: Copyright Opita Code (https://github.com/Opita-Code/opita-code)
```

Es una licencia permisiva con una restricción: el código se puede leer,
estudiar, modificar y compartir, y **cualquier uso comercial está prohibido**.
La organización que la concede puede, naturalmente, usarla como quiera.

## POR QUÉ ESTÁ Y NO OTRA

La decisión del operador: **no comercial, código abierto**. Es decir: que nadie
pueda tomar este código y vender un producto con el.

## LA DISTINCIÓN QUE NO CONVIENE SALTARSE

**PolyForm Noncommercial no está aprobada por la OSI.** Y la OSI es explícita
en los dos puntos:

> «Absolutely. All Open Source software can be used for commercial purpose;
> the Open Source Definition guarantees this. You can even sell Open Source
> software.»
> — OSI, *Can Open Source software be used for commercial purposes?*

> «No. The freedom to use the program for any purpose is part of the Open
> Source Definition. Open source licenses do not discriminate against fields of
> endeavor.»
> — OSI, *Can I restrict how people use an Open Source licensed program?*

Y sobre lo que no está aprobado:

> «Please don't do that. If you call it "Open Source" without using an
> approved license, you will confuse people.»
> — OSI, *Can I call my program "Open Source" even if I don't use an approved
> license?*

**Así que este repositorio no se autodenomina «open source».** No es una
cortesía: es que la Open Source Definition garantiza el uso comercial, y una
licencia que lo prohíbe no cumple esa definición. Decir «open source» aquí
sería una afirmación falsa, y este repositorio no dice afirmaciones falsas
para quedar bien: dice lo que es. **Código abierto con una restricción de uso
comercial.**

## LA ALTERNATIVA, SI EL ALCANCE QUISIERA SER Más ESTRECHO

Hay dos lecturas de «no comercial», y no son lo mismo:

| | Qué prohíbe | Qué permite |
|---|---|---|
| **PolyForm Noncommercial** (la elegida) | cualquier uso comercial del software, incluido prestarlo como servicio | leer, estudiar, modificar, compartir |
| **Commons Clause sobre MIT o Apache-2.0** | vender el software, es decir, distribuirlo por dinero | TODO lo anterior, y también ejecutarlo comercialmente |

Si la intención era **impedir la reventa y competitor**, y no impedir el uso
comercial, la segunda fila encaja mejor: con la primera, un servicio comercial
construido sobre este runtime tiene un problema; con la segunda, solo lo tiene
quien intenta vender el código.

**Y hay una tensión que hay que mirar de frente:** el plan del proyecto tiene
un modelo de negocio (marketplace, adopción comercial, puertas en Opita
Trabajos). Una licencia que prohíbe el uso comercial del software choca con
esa parte del plan. La decisión es del operador, pero conviene que sea
consciente de a qué parte del plan afecta, y no de que aparezca por sorpresa.

## LO QUE NO ES UN ABOGADO

Esto no es asesoramiento legal. La OSI dice de si misma que no da servicios
legales, y este documento tampoco. Para una decisión que ata al proyecto a
futuros, la respuesta correcta es un abogado con el que hablar, y este
documento es el resumen para que esa conversación empiece informada.
